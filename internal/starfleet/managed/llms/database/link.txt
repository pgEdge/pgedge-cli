##### pgedge starfleet managed database link

Write `.pgedge/link.yaml` in the current folder, naming one database,
or with `--branch` one of its branches. The file holds IDs only, so a
project can commit it. The database, and the branch, are read first:
an ID the profile cannot see is exit 4 and writes nothing. A folder
already linked elsewhere, or holding an unreadable link, is exit 1
unless `--force` is given. The home folder is refused at exit 2,
because `~/.pgedge` is the shared config folder; `unlink` and
`create --link` refuse it the same way.

With no ID and no terminal, `link` is exit 2, so always pass the ID.
With no ID in a terminal, it asks a person to choose the database,
then a branch, and offers to write `.env`. `--branch` without the
database ID is exit 2.

Below a linked folder, ten read verbs take the linked database when
the ID is left out, and print `Using database <id> from <path>` on
stderr when they do: `get`, `connection-string`, `inspect`, `logs`,
`metrics`, `wait`, `allowlist get`, `branch list`, `mcp connection`
and `env pull`. Every verb
that changes anything still requires its ID, so a script whose ID
variable is unset fails rather than writing to the linked database.
With a branch link, `connection-string`, `inspect`, `mcp connection`
and `env pull` read the branch, and the other six read the source
database.
The folder search stops at the first folder holding `.git`, and never
reads `~/.pgedge`.

**Example:**

```bash
pgedge starfleet managed database link e5f6a7b8-c9d0-1234-efab-567890123456
```
