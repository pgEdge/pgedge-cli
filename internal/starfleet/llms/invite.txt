### pgedge starfleet invite

**Usage:** `pgedge starfleet invite <command>`

Manage pgEdge Starfleet team invites

<!-- END GENERATED -->

#### invite

Manage Starfleet team invites — send, accept, and revoke invitations for
new team members.

There is no `status` field on an invite anywhere in this API. Do not
report an invite's "status".

<!-- BEGIN GENERATED: pgedge starfleet invite list -->
#### pgedge starfleet invite list

**Usage:** `pgedge starfleet invite list`

List invites

<!-- END GENERATED -->

**Example:**

```bash
pgedge starfleet invite list
```

**Example output (table):**

```
ID                                    EMAIL              INVITED BY  TEAM  EXPIRES     CREATED
d6e7f8a9-b0c1-2345-defa-456789012345  alice@example.com  bob         acme  2026-06-10  2026-06-03
```

`EXPIRES` and `CREATED` (like every other timestamp column in this
CLI) show only the date: an RFC3339 value is truncated to its first
10 characters.

Columns, in order: `ID`, `EMAIL`, `INVITED BY`, `TEAM`, `EXPIRES`,
`CREATED`. `INVITED BY` is blank when the API omits it. `-o json`
emits the raw API object, which also carries `token` (present when
the API returns one) and `accept_url` (`omitempty` in the schema) —
neither is guaranteed present on every invite.

#### pgedge starfleet invite get

**Usage:** `pgedge starfleet invite get [<invite_id>] [flags]`

Show invite details

**Flags:**

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--email string` | No |  | Find the invites for this email address instead of an ID |

<!-- END GENERATED -->

Get details for a specific invite. Same fields and column order as
`invite list`, for one invite.

`--email <addr>`, in place of the ID, prints every pending invite for
that address, compared without regard to case: an array under
`-o json`. It exits 4 when none matches; any other non-zero exit is a
failed read, not an absent invite.

**Example:**

```bash
pgedge starfleet invite get d6e7f8a9-b0c1-2345-defa-456789012345
pgedge starfleet invite get --email teammate@example.com -o json
```

#### pgedge starfleet invite create

**Usage:** `pgedge starfleet invite create [flags]`

Create an invite

**Flags:**

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--dry-run string[="checks"]` | No |  | Run every client-side check, then stop before sending the write and report the request that would have been sent. Checks that read the API do run, so this needs credentials; the server validates nothing until the real write |
| `--email string` | Yes |  | Email address to invite |
| `--expiration int` | No |  | Invite expiration in hours (optional) |

<!-- END GENERATED -->

**Needs a browser sign-in** (`pgedge starfleet auth login` with no
credential flags). With an API client, including the
`PGEDGE_CLIENT_ID`/`PGEDGE_CLIENT_SECRET` pair, it sends nothing and
exits **5** with `invite create needs a browser sign-in`; sign in
through the browser, or invite from the Team page in the Starfleet
UI. A blank `--email` exits 2.

On success it prints the new invite with `invite list`'s columns. The
invite's `token` and `accept_url` let anyone holding them join the
team: the table omits them, and `-o json` or `-o yaml` prints them.

**Example:**

```bash
pgedge starfleet invite create --email teammate@example.com
```

#### pgedge starfleet invite accept

**Usage:** `pgedge starfleet invite accept <invite_id> [flags]`

Accept an invite (needs the web UI)

**Flags:**

| Flag | Required | Default | Description |
|------|----------|---------|-------------|
| `--dry-run string[="checks"]` | No |  | Run every client-side check, then stop before sending the write and report the request that would have been sent. Checks that read the API do run, so this needs credentials; the server validates nothing until the real write |
| `--token string` | No |  | Invite token |

<!-- END GENERATED -->

**This does not run from the CLI.** Accepting an invite records
*which person* joined, and an API client names no person. Starfleet
derives identity from the token's claims, where a user token sets
`X-User-ID` and a client token sets `X-Client-ID` but never both, and
answers 401 on an empty user ID. The CLI does not send the request for a browser
sign-in either, so it refuses before making the request, whichever
way it signed in, and exits **5**.

The operation is excluded from the published public API contract.

Accept an invite from the link in the invitation email, or in the
Starfleet UI.
